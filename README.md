# NewDay — планировщик дня и трекер привычек

Веб-приложение и Android-приложение для планирования дня, контроля привычек
и печати дневного листа. Работает у себя на сервере одной командой.

**Сайт-пример:** https://newday.appswire.ru · **Лицензия:** MIT ·
[English](#english)

---

## Что это

Инструмент, чтобы держать день под контролем, а не список задач.

- **Расписание дня** двумя видами: списком и таймлайном. Слева рельс, по которому
  движется настоящее: текущая строка подсвечена и показывает, сколько до её конца,
  прошедшее приглушено.
- **Будильник в Android-приложении**, который действительно будит: звучит
  в беззвучном режиме и при «Не беспокоить», поднимает экран поверх блокировки,
  переживает перезагрузку и требует решить задачу, чтобы выключиться.
- **Привычки** с челленджами: «30 дней подряд», «марафон 300 дней», «бросаю».
  Три независимые настройки — цель, поведение при срыве, что именно отмечается.
- **Печать на лист A4** под ручку: план слева, колонка «факт» справа, линейки
  для заметок. Не влезло — приложение спросит, уменьшить шрифт или разбить на два листа.
- **API с персональными токенами**, чтобы заполнять день из бота или нейросети.
- Светлая и тёмная темы, работа с телефона и с компьютера, экспорт и импорт данных.

## Быстрый старт (локально)

### Требования
- Node.js 22+ (на нём же собирается контейнер и идёт CI)

### Установка
```bash
npm install
cp .env.example .env
# Отредактируйте .env — смените SESSION_SECRET
```

### Запуск
```bash
npm start
# или для разработки:
npm run dev
```

Откройте в браузере: **http://localhost:3000**


1. Загрузите проект в Git-репозиторий.
2. В Coolify создайте новый сервис → **Docker Compose**.
3. Укажите URL репозитория.
4. Coolify автоматически найдёт `docker-compose.yaml` в корне.
5. Добавьте переменные окружения из `.env.example` в настройках Coolify:

   - `DB_PATH` — `/app/data/newday.db`

7. Volume `./data:/app/data` обеспечивает сохранение базы данных.

## Использование

### Экран дня

Слева от расписания идёт вертикальный рельс, по которому движется настоящее:
текущая строка подсвечена и показывает, сколько до её конца, прошедшие приглушены.
День переключается стрелками в шапке, свайпом на телефоне или кнопкой «Сегодня».
Отдельного действия «создать день» нет — день появляется, как только в него что-то записали.

- **Расписание** — два вида, переключатель `☰ / ▦` в заголовке секции. Список компактнее
  и печатается, таймлайн показывает длительность и дыры в дне. На бумагу всегда идёт список.
- **Сдвиг времени** — кнопка `⏱` на строке: `+15`, `+30`, `−15` или произвольно,
  с галочкой «и все следующие». Это сценарий «задержался на обеде».
- **Напоминания** — иконка на строке переключает `тихо → уведомление → будильник`.
  Уведомление приходит в браузер и на телефон за заданное время до начала,
  будильник звонит в срок и будит по-настоящему — но только в приложении.
- **Разделы дня** — работа, дом, питание и спорт идут отдельными блоками друг
  под другом, а не вкладками: вкладки прятали три четверти дня и заставляли
  листать, чтобы просто посмотреть, что осталось. Режим питания (чек-лист или
  приёмы пищи по времени) выбирается в настройках.
- **Спорт таблицей**: у столбцов есть подписи — подходы, повторы, вес. Отмеченное
  упражнение не перечёркивает цифры: `4×12, 60 кг` — это запись сделанного.
  Там же контроль веса: пусто — значит ни на экране, ни на бумаге ничего нет.
- **Прогресс дня — только то, что вы отмечаете сами**: дела, питание, спорт,
  привычки. Расписание в него не входит: про время знают часы, а не галочки
  напротив «Подъём». Подробнее — в [docs/логика.md](docs/логика.md).
- **Повторы** — правило живёт отдельно от дня. Изменение или удаление одного дня
  не ломает серию; серию можно завершить с любой даты, не трогая прошлое.

### Привычки

Создание в один шаг: эмодзи, название, пресет. Пресеты разворачиваются в три
независимые настройки, которые можно задать и по отдельности:

| Ось | Значения |
|---|---|
| Цель | бессрочно · челлендж на N дней |
| При срыве | начинать заново · копить дальше |
| Что отмечаю | сделал · удержался (для «бросаю») |

Плюс дни недели, количество в день и «заморозки» — пропуски, которые не портят серию
и не входят в процент. Удаление по умолчанию отправляет в архив: история отметок остаётся.

### Печать

Кнопка `🖨` открывает диалог: что печатать и что делать, если день не помещается
на лист — уменьшить шрифт или разложить на две страницы. Лист чёрно-белый,
галочки печатаются рамкой, справа от каждой строки идёт колонка «факт»,
внизу — линейки для рукописных заметок.

### Темы

Светлая, тёмная и системная. Выбор хранится локально (чтобы страница не мигала
при загрузке) и на сервере (чтобы совпадал между устройствами).

### Вход с телефона

Настройки → «Показать код для входа» → отсканировать QR приложением.
Код одноразовый и живёт две минуты; рядом есть восьмизначный код на случай,
если камера не сработала. Подключённые устройства видны списком и отзываются одной кнопкой.

## Иконки

Все иконки — веб, PWA, Android adaptive icon, splash — генерируются из одного
файла `brand-icon.png` (квадратный PNG, лучше 1024×1024 и больше):

```bash
pip install Pillow
python tools/make-icons.py
```

Скрипт сам подберёт плотности, вырежет maskable-версию с полями под safe-zone
и подставит фоновый цвет adaptive-иконки, взятый из краёв самого изображения.
Чтобы поменять иконку, достаточно заменить `brand-icon.png` и запустить скрипт.

## Android-приложение

Приложение — это Capacitor: та же веб-часть, вшитая в APK, плюс нативный модуль
будильника на Kotlin. Веб-ассеты внутри пакета, поэтому приложение открывается
без интернета, а к серверу обращается по абсолютному адресу с токеном устройства.

```bash
npm install
python tools/make-icons.py     # если менялась иконка
npx cap sync android           # переносит public/ в проект Android
cd android && ./gradlew assembleDebug
```

Готовый APK: `android/app/build/outputs/apk/debug/app-debug.apk`.

### Своя релизная сборка

Android не устанавливает неподписанный APK, поэтому для распространения нужен
свой ключ. В репозитории его быть не должно — путь передаётся окружением:

```bash
keytool -genkeypair -keystore newday.keystore -storetype PKCS12 -alias newday \
  -keyalg RSA -keysize 4096 -validity 10000

export NEWDAY_KEYSTORE=/абсолютный/путь/newday.keystore
export NEWDAY_KEYSTORE_PASSWORD=…
cd android && ./gradlew assembleRelease
```

Без `NEWDAY_KEYSTORE` релиз подписывается отладочным ключом: поставить такой
APK себе можно, но обновить его потом настоящим ключом уже нельзя — Android
откажется из-за несовпадения подписи.

Ключ подписи нельзя терять: без него не выпустить обновление, которое встанет
поверх установленного приложения. Храните его отдельно от репозитория и с
резервной копией.

Релизную сборку по тегу `v*` делает CI и прикладывает к GitHub-релизу; ключ
берётся из секретов `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
`ANDROID_KEY_ALIAS`. Версия приложения берётся из тега: `v1.2.3` →
`versionName 1.2.3`, `versionCode 10203`.

### Обновление приложения

APK раздаёт сам сайт: `GET /api/v1/app/download`. Файл лежит рядом с базой —
в том же постоянном томе, поэтому переживает пересборку контейнера. В git
четырёхмегабайтный бинарник не кладём.

Приложение при запуске спрашивает `GET /api/v1/app/version` и, если на сервере
версия новее, предлагает обновиться. **«Позже» откладывает вопрос до следующего
дня**, а не до следующего запуска: иначе предложение превращается в помеху,
которую закрывают не читая. Проверить и обновиться вручную можно в
**Настройки → Приложение для Android → Версия** в любой момент.

Скачивает и устанавливает нативная часть: страница живёт на origin
`https://localhost`, и записать файл на диск оттуда некуда, а установщику нужен
именно файл. Устанавливает не приложение, а системный установщик — мы только
показываем ему файл через `FileProvider`; подтверждает человек.

Новую сборку выкладывает CI сразу после того, как собрал:

```bash
curl -X POST "https://ваш-сайт/api/v1/app/upload?versionName=1.0.1" \
  -H "X-Upload-Token: $APK_UPLOAD_TOKEN" \
  -H "Content-Type: application/octet-stream" \
  --data-binary @NewDay-1.0.1.apk
```

Версию старше или равной выложенной сервер не принимает (409): подмена свежего
APK старым — самый неприятный способ сломать обновление. Держатся три последние
версии, чтобы можно было откатиться.

Обновление встанет только если подписано **тем же ключом**, что установленная
версия. Отсюда и требование не терять keystore: с другим ключом Android
откажется обновлять, и людям придётся удалять приложение вместе с данными.

Сравниваются `versionCode`, а не строки версий: «1.10» как строка меньше «1.9»,
хотя новее.

### Как устроен будильник

| Механизм | Зачем |
|---|---|
| `AlarmManager.setAlarmClock()` | точный запуск, переживает Doze и энергосбережение |
| `STREAM_ALARM` + канал с `bypassDnd` | звучит в беззвучном режиме и при «Не беспокоить» |
| Full-screen intent + `showWhenLocked` | экран включается и открывается поверх блокировки |
| Foreground-сервис + `WakeLock` | процесс не убьют и экран не погаснет во время звонка |
| `BOOT_COMPLETED` | будильники восстанавливаются после перезагрузки |
| `SYSTEM_ALERT_WINDOW` | без него система не даёт поднять экран из фона на разблокированном телефоне |

### Мягкое начало

Частый случай: человек встал сам в 9:50, а будильник всё равно звонит в 10:00.
Решать в этот момент примеры незачем — достаточно выключить.

Поэтому будильник начинает тихо: примерно 15 % громкости, короткая вибрация и
одна большая кнопка «Выключить» с обратным отсчётом. Сколько длится окно,
задаётся в **Настройки → Поведение будильника** (по умолчанию минута, можно
выключить совсем). Не выключили за это время — значит, скорее всего, спят:
громкость идёт вверх, вибрация становится настойчивее, появляются задачи.

Время окна считает сервис будильника, а не экран. Если система задержала
показ окна или не дала его поднять вовсе, тихая фаза всё равно закончится
вовремя и будильник заорёт — иначе выключенный звук превратился бы в
непрозвонивший будильник.

Все разрешения видны в приложении в **Настройки → Будильник**: у каждого
объяснено, зачем оно нужно, и есть кнопка, ведущая ровно в нужный системный
экран. Там же тестовый будильник — убедиться, что он сработает на конкретном
телефоне, можно только дав ему сработать.

Живая проверка на эмуляторе или телефоне:

```bash
bash tools/alarm-emulator-test.sh --with-reboot
```

Десять сценариев: заблокированный экран, громкость под управлением приложения,
режим полной тишины, Doze, убитый процесс, отсутствие сети, перезагрузка
устройства — и три на мягкое начало: выключение одной кнопкой, самостоятельный
переход к задачам по истечении окна, задачи сразу при выключенном окне.
Проверки идут при убитом процессе и погашенном заблокированном экране.

Проверки написаны так, чтобы не проходить впустую. Два примера, на которых
это уже сработало:

- сценарий «беззвучный режим» гасил звук командой `adb shell media volume`,
  которой на образе эмулятора нет: команда не находилась, громкость не менялась,
  и сценарий проходил, ничего не проверив. Задать громкость снаружи там нельзя
  вообще — ни командой, ни клавишами. Поэтому теперь сравниваются два замера
  во время звонка: в мягком начале поток будильника стоит на 1 из 7, после
  окна — на 7. Это и есть доказательство, что громкость выставляет приложение;
- сценарий «Не беспокоить» теперь сначала читает `zen_mode` и требует, чтобы
  режим действительно включился.

Заодно нижняя граница громкости будильника в Android — не ноль, а один:
поток будильника заглушить нельзя, поэтому беззвучный режим на него не влияет.

Проверка ставит будильники через настоящий плагин, а для этого ей нужен доступ
к странице по отладочному протоколу — то есть отладочная сборка. В релизе этот
доступ закрыт намеренно: он открывает содержимое страницы любому, кто может
выполнить `adb` на телефоне, а там лежит токен устройства.

> Принудительная остановка приложения в настройках Android отключает его
> будильники, пока приложение не запустят снова. Это поведение системы, обойти
> его нельзя — штатный будильник Google ведёт себя так же.

## API

Полная спецификация — **`/api/v1/openapi.json`**, человекочитаемая страница — **`/api/docs`**.

Аутентификация — cookie-сессия (веб) либо персональный токен: `Authorization: Bearer nd_…`.
Токен создаётся в настройках и показывается один раз; есть режимы «только чтение» и «чтение и запись».

```bash
curl -H "Authorization: Bearer nd_xxxxxxxx_..."      https://newday.appswire.ru/api/v1/days/2026-08-03/full
```

Заполнить день целиком — например, из бота или LLM. Нужен заголовок `If-Match`
с текущим `rev` дня (для нового дня это `0`):

```bash
curl -X PUT -H "Authorization: Bearer nd_..."      -H "Content-Type: application/json" -H 'If-Match: "0"'      -d '{"title":"План","schedule":[{"time":"06:00-06:30","title":"Подъём","alarmMode":"alarm"}]}'      https://newday.appswire.ru/api/v1/days/2026-08-04/full
```

Основные группы: `/auth/*`, `/days/*` (плюс вложенные `schedule`, `tasks`, `meals`, `sport`),
`/habits/*`, `/stats`, `/settings`, `/tokens`, `/devices`, `/export`, `/import`.

Старые пути `/api/auth/*`, `/api/days/*`, `/api/habits/*` работают как алиасы
и будут удалены после переписывания фронтенда.

### Модель данных

День больше не хранится одним JSON-блобом: расписание, задачи, питание и спорт лежат
в отдельных таблицах, и каждый эндпоинт правит одну строку. У дня есть счётчик версий
`rev` — он нужен только двум операциям, переписывающим день целиком
(`PUT /days/{date}/full` и `PATCH /days/{date}`). Правки отдельных строк между собой
не конфликтуют, поэтому телефон и компьютер могут работать с одним днём одновременно.

Даты — строки `YYYY-MM-DD` в таймзоне пользователя (`Europe/Moscow` по умолчанию).
Время — целые минуты от полуночи.

### Выгрузка

`GET /api/v1/export` — всё в своём JSON, им же данные загружаются обратно
(`POST /api/v1/import`, режимы «дополнить» и «заменить»).

`GET /api/v1/export.ics` — расписание в формате календаря: открывается
в Google Calendar, Apple Calendar и почти где угодно. Задачи и привычки туда
не идут — у них нет времени начала, событиями они не являются. Приём пищи
попадает, только если у него задано время.

## English

**NewDay** is a self-hosted day planner and habit tracker: a web app plus an
Android app whose alarm actually wakes you up.

### Highlights

- **Day schedule** in two views — list and timeline. A rail on the left tracks the
  present moment: the current row is highlighted with time remaining, past rows dim.
- **A real Android alarm.** Rings through silent mode and Do Not Disturb, shows a
  full-screen screen over the lock screen, survives reboot, and refuses to stop until
  you solve a task (math, code or icon sequence). It starts quiet, though: for the
  first minute — configurable, or off — there is just one big "Dismiss" button, because
  if you are already awake, solving puzzles is pointless. Miss that window and the
  volume climbs and the tasks appear. Verified on an emulator across ten scenarios:
  locked screen, silent mode, DND, Doze, killed process, no network, reboot, and three
  for the quiet start.
- **Habits with challenges** — "30 days in a row", "300-day marathon", "quitting".
  Three independent axes: goal, what happens on a miss, and what you actually mark.
- **A4 print** designed for a pen: plan on the left, an "actual" column on the right,
  ruled lines for notes. If the day does not fit, the app asks whether to shrink the
  type or split across two sheets instead of silently cutting it off.
- **REST API with personal tokens** so a bot or an LLM can fill in your day.
- Light and dark themes, works on phone and desktop, JSON export and import.

### Run it

```bash
git clone https://github.com/DanT2000/NewDay
cd NewDay
cp .env.example .env      # change SESSION_SECRET
docker compose up -d
```

Open http://localhost:3000 and register. The first account becomes the admin.

Email confirmation and web push are optional: without `SMTP_HOST` the app skips
address verification, and without VAPID keys it simply does not send push. Nothing
else is required to run.

### API

Full spec at `/api/v1/openapi.json`, human-readable page at `/api/docs`.
Authenticate with a cookie session (web) or a personal token:

```bash
curl -H "Authorization: Bearer nd_xxxxxxxx_..." \
     https://your-server/api/v1/days/2026-08-03/full
```

### Android

```bash
npm install
npx cap sync android

# Android refuses to install an unsigned APK, so bring your own key
keytool -genkeypair -keystore newday.keystore -storetype PKCS12 -alias newday   -keyalg RSA -keysize 4096 -validity 10000
export NEWDAY_KEYSTORE=/absolute/path/newday.keystore
export NEWDAY_KEYSTORE_PASSWORD=…

cd android && ./gradlew assembleRelease
```

Without `NEWDAY_KEYSTORE` the release is signed with the debug key: installable
for yourself, but a properly signed build can never update it — Android rejects
a signature change. Keep the keystore outside the repository and back it up;
losing it means never shipping an update again.

CI builds an APK on every `v*` tag and attaches it to the GitHub release, taking
the key from the `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD` and
`ANDROID_KEY_ALIAS` secrets. The tag sets the version: `v1.2.3` becomes
`versionName 1.2.3`, `versionCode 10203`.
The app bundles its web assets, so it works offline; it authenticates with a
device token, obtained either by signing in or by scanning a QR code from the
desktop.

**One thing no app can work around:** if you force-stop the app in Android
settings, the system stops delivering its alarms until you launch it again.
Google's own Clock behaves the same way.
