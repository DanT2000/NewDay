# NewDay Этап 2 — Веб-интерфейс. План реализации

> Продолжение этапа 1. Спека: `docs/superpowers/specs/2026-08-03-newday-production-design.md`, разделы §6 и §7.

**Goal:** Один интерфейс на компьютер и телефон поверх API v1: экран дня в двух видах, привычки с челленджами и эмодзи-пикером, статистика, светлая и тёмная темы, печать на один лист A4, настройки с токенами и QR.

**Architecture:** `public/app.js` (2100 строк, два независимых рендерера) разбивается на ES-модули без сборщика. Один набор компонентов, раскладка через CSS-грид и медиазапросы — никакого ветвления `isMobile()` в логике. Состояние в одном сторе с подписками; все записи идут через оптимистичное обновление с откатом по ошибке.

**Tech Stack:** Vanilla ES-модули (`<script type="module">`), CSS custom properties, inline SVG. Ни сборщика, ни фреймворка, ни CDN — ассеты должны копироваться в APK как есть.

## Global Constraints

- Ни одного внешнего запроса: ни CDN, ни шрифтов, ни аналитики. Всё, что нужно, лежит в `public/`.
- Только `/api/v1/*`. Старые пути не используются — они остаются лишь для обратной совместимости.
- Каждый модуль в `public/js/` — одна ответственность, до ~300 строк.
- Темы задаются CSS-переменными в `:root` и `[data-theme="dark"]`. Никаких хардкод-цветов в компонентах.
- Всё, что видит пользователь, — по-русски. Ошибки сервера показываются из `error.message`.
- Файлы, которые нужны офлайн в APK, перечислены в `service-worker.js`.
- Ширина от 320px. Горизонтальной прокрутки страницы быть не должно.
- Каждая задача заканчивается коммитом в `develop`.

### Task 1: Брендинг — иконки из `icon.png`

**Files:** `public/icons/*`, `public/manifest.webmanifest`, `tools/make-icons.py`, `public/login.html`, `public/register.html`

Из `icon.png` 800×800 генерируются: `favicon.png` 32, `icon-192.png`, `icon-512.png`, `icon-maskable-512.png` (с полями 10% под safe-zone), `apple-touch-icon.png` 180, `logo-256.png` для экранов входа. Скрипт `tools/make-icons.py` кладётся в репозиторий, чтобы иконку можно было заменить одной командой. Манифест обновляется: имя, цвета `#2E7BE4`, `display: standalone`, `maskable`-иконка.

**Готово, когда:** на экране входа виден логотип, во вкладке браузера — favicon, `manifest.webmanifest` проходит проверку установки PWA.

---

### Task 2: Дизайн-система — токены, темы, база стилей

**Files:** `public/css/tokens.css`, `public/css/base.css`, `public/css/components.css`, `public/js/theme.js`

Переменные: цвета (акценты `#2E7BE4`, `#FF9E1B`, `#22C1D6` из иконки), поверхности, текст, границы, тени, радиусы, отступы по шкале 4px, типографика. Тёмная тема — отдельный набор значений, не инверсия.

`theme.js`: три состояния (`system` / `light` / `dark`), значение читается из `localStorage` до первой отрисовки (чтобы не мигало) и синхронизируется в `PATCH /api/v1/settings`.

Компоненты: кнопка, поле, чекбокс, карточка, вкладки, модалка, нижний лист, тост, кольцо прогресса.

**Готово, когда:** демо-страница `public/kitchen-sink.html` показывает все компоненты в обеих темах без визуальных дефектов.

---

### Task 3: Ядро фронтенда — api, store, dates

**Files:** `public/js/api.js`, `public/js/store.js`, `public/js/dates.js`, `public/js/toast.js`

- `api.js`: обёртка над fetch, единый разбор `{error:{code,message}}`, автоматический `If-Match` из текущего `rev`, повтор один раз при `409` с перечитыванием, редирект на `/login.html` при `401`.
- `store.js`: `state`, `subscribe(fn)`, `mutate(fn)`, оптимистичные операции с откатом. Один источник правды на день.
- `dates.js`: тот же набор, что на сервере (`todayFor`, `addDays`, `rangeDates`, `weekdayOf`, `parseTimeToMinutes`, `formatMinutes`), плюс форматирование по-русски.

**Готово, когда:** тесты чистых функций `dates.js` в `test/web/dates.test.js` проходят под `node --test`.

---

### Task 4: Экран дня — каркас, полоска дат, шапка

**Files:** `public/app.html`, `public/js/views/day.js`, `public/js/views/datestrip.js`, `public/js/views/calendar.js`

Шапка: логотип, полоска ближайших дней со стрелками, кнопка «Сегодня», календарь за кнопкой, переключатель темы, настройки. Свайп по горизонтали на телефоне. Заголовок дня, фокус, вес с дельтой, общий прогресс.

Отдельного действия «Добавить день» нет: день создаётся при первой правке.

---

### Task 5: Расписание — список и таймлайн

**Files:** `public/js/views/schedule-list.js`, `public/js/views/schedule-timeline.js`, `public/js/components/drag.js`, `public/js/components/timeinput.js`

Переключатель видов сохраняется в настройках. Перетаскивание за ручку через Pointer Events (мышь и палец). Кнопка `⏱` — сдвиг `+15/+30/−15/произвольно` с галочкой «и все следующие», уходит в `POST /schedule/shift`. Иконка-цикл будильника `· → 🔔 → ⏰`. Свободный ввод времени.

---

### Task 6: Задачи, питание, спорт, заметки

**Files:** `public/js/views/tasks.js`, `public/js/views/meals.js`, `public/js/views/sport.js`, `public/js/views/notes.js`

Три вкладки «Работа · Дом · Питание» в одном блоке. Питание рендерится в режиме из `foodMode`; в режиме `timed` записи с временем дополнительно показываются в расписании только для чтения. Заметки — автосохранение по паузе ввода, а не по каждому символу.

---

### Task 7: Повторы и шаблоны (backend + UI)

**Files:** `server/repos/series.js`, `server/services/seriesService.js`, `server/routes/v1/series.js`, `public/js/views/repeat.js`, `test/api/series.test.js`

Правило хранится в `series`, конкретный день переопределяет своё вхождение через `series_overrides`. Материализация при чтении дня: строки серии подмешиваются в расписание, если на эту дату нет `deleted`-override. Правка одной строки серии предлагает выбор «только этот день / всю серию».

Шаблон — `series` с именем и без дат, применяется вручную через `POST /days/:date/apply-template`.

**Готово, когда:** тесты покрывают ежедневное правило, «по будням», «каждые 2 недели», удаление одного дня и досрочное завершение серии.

---

### Task 8: Привычки — экран управления, пресеты, эмодзи-пикер

**Files:** `public/js/views/habits.js`, `public/js/views/habit-editor.js`, `public/js/emoji.js`, `public/js/emoji-data.json`

Создание в один шаг: эмодзи · название · пресет. Под «Настроить» — дни недели, тип, цель за день, заморозки, полярность, поведение при срыве, дата старта.

Эмодзи-пикер: около 600 эмодзи по категориям, поиск по русским названиям, недавние в `localStorage`. Данные локальные.

Карточка: `🚭 Не курить · 47-й день из 300 · 2 срыва · ██████░░ 78%` и точки последних 14 дней.

---

### Task 9: Прогресс и статистика

**Files:** `public/js/views/progress.js`, `public/js/views/stats.js`, `public/js/components/chart.js`

Кольца: общий плюс работа, дом, питание, спорт, привычки. Периоды 7/30/90/всё. Графики — inline SVG, читаемые в обеих темах. История веса с мини-графиком.

---

### Task 10: Печать

**Files:** `public/js/views/print.js`, `public/css/print.css`

Один лист A4 по умолчанию, чёрно-белый. Превью с настоящими границами страниц. Если не влезает — выбор «уменьшить шрифт» или «на два листа», без молчаливой обрезки. Чекбоксы печатаются пустыми квадратами, фоновых заливок нет. Выбор блоков перед печатью, колонка «факт» рядом с планом.

---

### Task 11: Настройки

**Files:** `public/js/views/settings.js`, `public/js/views/tokens.js`, `public/js/qr.js`, `public/pair.html`, `public/reset.html`

Разделы: профиль и таймзона, тема, вид расписания, режим питания, перенос задач, API-токены (создание со скоупом, показ секрета один раз, отзыв), устройства и вход по QR, приложение для Android, экспорт и импорт.

Генератор QR вендорится (MIT, ~5 КБ) в `public/js/vendor/qr.js`. Страница `/pair` принимает код из хеша. Страница `/reset.html` завершает сброс пароля.

---

### Task 12: Сборка воедино, PWA, приёмка

**Files:** `public/service-worker.js`, `public/index.html`, удаление старого `public/app.js`

Service worker кеширует оболочку и ассеты, данные всегда с сети. Старый `app.js` удаляется, legacy-роуты на сервере остаются до этапа 5.

**Приёмка:** полный сценарий дня на десктопе и на телефоне (эмулятор Chrome 360×740), обе темы, печать умещается на лист, вход по QR с телефона, заполнение дня токеном из curl видно в интерфейсе после обновления.
