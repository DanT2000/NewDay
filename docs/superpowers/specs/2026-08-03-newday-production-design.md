## 1. Цель

NewDay — личный планировщик дня и трекер привычек. Сейчас это демо: работает, но теряет данные, врёт в статистике и не имеет пригодного мобильного приложения.

Задача — довести до состояния, когда:

- данные не теряются ни при каком сценарии использования;
- статистика и прогресс считаются корректно;
- есть удобный веб-интерфейс на компьютере и телефоне в светлой и тёмной теме;
- есть Android-приложение с уведомлениями и будильником, который **действительно** будит;
- есть публичное API с персональными токенами, чтобы день можно было заполнять из LLM или бота;
- проект можно опубликовать на GitHub и развернуть у себя командой `docker compose up`.

## 2. Что сломано сейчас и почему

Причины, а не симптомы. Каждая закрывается конкретным решением ниже.

| # | Проблема | Корень | Где чинится |
|---|---|---|---|
| 1 | Прогресс «скидывался по всем дням» | `public/app.js:163` — при любой осечке загрузки дня (обрыв сети, протухшая сессия, 404) `S.selectedDay` подменяется пустым `{date}`. Следующее нажатие клавиши запускает дебаунс, и `PUT /api/days/:date` с телом `{date}` затирает день целиком. Ошибка молчаливая | §4, §5 |
| 2 | Привычки, заметки, расписание «криво работали» | День хранится одним блобом `days.data_json`; клиент по дебаунсу 800 мс шлёт `PUT /api/days/:date` со всем объектом. Вторая вкладка, телефон, гонка запросов или обрыв сети затирают день целиком | §4, §5 |
| 2b | Строки расписания «прыгают», правки уезжают не в ту строку | Сервер сортирует расписание в `sortSchedule()` при сохранении, но возвращает только `{success:true}`. Клиент остаётся со стало́й несортированной копией и правит строки по индексам | §4.1, §5.3 |
| 3 | Случайные пустые дни | `PUT /api/days/:date` создаёт день, если его нет | §5.3 |
| 4 | Стрики и проценты «едут» | Сервер считает «сегодня» как `new Date().toISOString()` — это UTC. С 00:00 до 03:00 МСК сервер думает, что сегодня ещё вчера | §4.3 |
| 5 | Статистика привычек занижена | Считается от `created_at` привычки по сегодня; каждый день без отметки — минус. Нет графика привычки, нет различия «не отмечено» / «не сделал» | §4.2, §7 |
| 6 | Часть функций есть только на десктопе | В `app.js` два независимых рендерера (`renderDay*` и `renderMobile*`), разошлись по возможностям | §6.1 |
| 7 | Выбор эмодзи не работает | Не реализован | §7.3 |
| 8 | Android бесполезен | Capacitor-WebView на удалённый URL: без сети не открывается, уведомлений и будильника нет, иконка дефолтная. Каталог `android/` в `.gitignore` — нативного проекта нет в репозитории | §8 |
| 9 | Нет почты, восстановления пароля, API-токенов | Не реализовано | §5.4, §5.5 |
| 10 | `.env` с `SESSION_SECRET` закоммичен | Репозиторий планируется открыть | §10 |

## 3. Принятые решения

| Вопрос | Решение |
|---|---|
| Android | Capacitor + собственный нативный Kotlin-плагин. Веб-ассеты вшиты в APK, приложение работает офлайн |
| Поставка | Пять этапов, каждый деплоится в прод. Staging не заводим |
| Вид расписания | Оба: список и таймлайн, переключатель в интерфейсе, выбор запоминается |
| Регистрация | По email, подтверждение обязательно. Отключается автоматически, если SMTP не настроен |
| Питание | Оба режима: чек-лист и приёмы пищи по времени. Переключается в настройках, данные общие |
| Задачи для отключения будильника | Все три типа сразу: пример, код, иконки |
| QR-код | Два разных: публичный на скачивание APK и приватный на вход по устройству |
| Существующие данные | Миграция из `data_json` делается автоматически, но не является блокирующей: потеря допустима |

## 4. Модель данных

SQLite. Ранер миграций по `schema_version`, выполняется при старте сервера, идемпотентен.

### 4.1 Схема

```sql
users
  id, email UNIQUE NULL, email_verified INTEGER DEFAULT 0,
  username UNIQUE NULL,              -- legacy, для мигрированных аккаунтов
  password_hash, display_name,
  timezone TEXT DEFAULT 'Europe/Moscow',   -- IANA
  theme TEXT DEFAULT 'system',             -- system | light | dark
  week_start INTEGER DEFAULT 1,            -- 1 = понедельник
  schedule_view TEXT DEFAULT 'list',       -- list | timeline
  food_mode TEXT DEFAULT 'checklist',      -- checklist | timed
  is_admin INTEGER DEFAULT 0,

email_tokens
  id, user_id, kind TEXT,            -- verify | reset

  id, user_id, name, prefix, token_hash,
  scope TEXT,                        -- read | write   (write включает read)

  id, user_id, name, platform, token_hash,
  last_seen_at, revoked_at, created_at

  id, user_id, code_hash, short_code, expires_at, claimed_at

  id, user_id, date TEXT,            -- YYYY-MM-DD в таймзоне пользователя
  title, focus, weight REAL NULL, notes,
  rev INTEGER DEFAULT 1,

  id, user_id, date,

  id, user_id, date, exercise, sets INTEGER, reps INTEGER,
  weight REAL NULL, done INTEGER DEFAULT 0, sort_order INTEGER,
  created_at, updated_at

  id, user_id, target TEXT,                  -- schedule | task | meal
  freq TEXT,                                 -- daily | weekly | monthly
  interval INTEGER DEFAULT 1,
  byweekday INTEGER DEFAULT 127,             -- битовая маска пн..вс
  start_date, end_date NULL,
  payload_json,                              -- шаблон элемента
  name TEXT NULL,                            -- заполнено => это шаблон, применяется вручную
  created_at, updated_at

  id, user_id, series_id, date,
  action TEXT,                               -- modified | deleted
  UNIQUE(series_id, date)

  id, user_id, title, emoji, color, description,
  type TEXT DEFAULT 'binary',                -- binary | quant
  target_per_day INTEGER NULL, unit TEXT NULL,
  schedule_mask INTEGER DEFAULT 127,         -- в какие дни недели привычка активна
  polarity TEXT DEFAULT 'do',                -- do | avoid
  mode TEXT DEFAULT 'ongoing',               -- ongoing | challenge

  challenge_start_date TEXT NULL,

  id, user_id, habit_id, date,
  status TEXT,                               -- done | missed | skipped
  value INTEGER NULL,                        -- для type='quant'

  UNIQUE(user_id, habit_id, date)

Индексы на `(user_id, date)` во всех дневных таблицах, на `(user_id, habit_id, date)` в `habit_logs`, на `fire_at_utc` в `notification_queue`.

### 4.2 Почему `status` вместо `done 0/1`

Сейчас отсутствие записи и «не выполнил» неразличимы, поэтому проценты врут. Три состояния:

- `done` — выполнено;
- `missed` — явно отмечено как невыполненное (или день прошёл, а привычка была активна);
- `skipped` — заморозка, в знаменатель процента не попадает.

Отсутствие записи за прошедший день трактуется как `missed`, за сегодня и будущее — как «ещё не решено».

### 4.3 Часовой пояс

`users.timezone` (IANA). Все вычисления «сегодня», границ суток, стриков и процентов выполняются в зоне пользователя. Даты в БД — строки `YYYY-MM-DD`, локальные для пользователя: день здесь календарное понятие, а не момент времени. В UTC переводится только `notification_queue.fire_at_utc`.

Единая серверная утилита `todayFor(user)` и `localDate(user, instant)`; прямые вызовы `new Date().toISOString()` для получения даты запрещены.

### 4.4 Миграция существующих данных

Текущая схема считается версией 1. Нормализация — миграция 2, она выполняется один раз при старте: для каждой строки `days` разобрать `data_json` и разложить `title/focus/weight/notes` в `days`, `schedule` в `schedule_items`, `workTasks`/`homeTasks` в `tasks`, `sport` в `sport_sets`. Существующие `habit_logs.done` → `status` (`1 → done`, `0 → missed`). Исходный `data_json` сохраняется в `days.legacy_json` и не удаляется. Пользователи без email сохраняют вход по `username` и при первом входе получают предложение привязать почту.

## 5. Сервер и API

### 5.1 Принципы

- Один эндпоинт правит одну сущность. Никаких «PUT весь день» из UI.
- `days.rev` увеличивается на единицу при любом изменении внутри дня, включая вложенные сущности.
- Заголовок `If-Match: <rev>` **обязателен** для двух операций, которые переписывают день целиком: `PUT /days/:date/full` и `PATCH /days/:date`. При расхождении — `409` с актуальным состоянием дня; клиент перечитывает, мержит и повторяет.
- Операции над отдельными сущностями (`schedule`, `tasks`, `meals`, `sport`) `If-Match` **не требуют** — они правят одну строку и между собой не конфликтуют. Защита от перезаписи чужой правки той же строки — через `updated_at` строки в теле запроса; несовпадение даёт `409`.
- Все ответы — JSON. Ошибки в едином формате `{ error: { code, message, details? } }`.
- Rate limit на `/api/v1/auth/*` и на токен-аутентифицированные запросы.

### 5.2 Аутентификация

Три способа на одних и тех же путях:

1. Cookie-сессия (веб). `secure: true`, `sameSite: 'lax'`, `app.set('trust proxy', 1)` — сейчас `secure: false` за HTTPS-прокси.
2. `Authorization: Bearer nd_<prefix>_<secret>` — персональный API-токен.
3. `Authorization: Bearer ndd_<...>` — device-токен, выданный по QR.

### 5.3 Дневные ресурсы

```

PATCH  /api/v1/days/:date                    частично: title, focus, weight, notes
DELETE /api/v1/days/:date

POST   /api/v1/days/:date/schedule           создать строку
PATCH  /api/v1/days/:date/schedule/:id
DELETE /api/v1/days/:date/schedule/:id
POST   /api/v1/days/:date/schedule/reorder   { ids: [...] }
POST   /api/v1/days/:date/schedule/shift     { fromId, minutes, cascade: bool }

POST | PATCH | DELETE   /api/v1/days/:date/tasks[/:id]
POST | PATCH | DELETE   /api/v1/days/:date/meals[/:id]

`PUT /api/v1/days/:date/full` — единственное место, где день заменяется целиком, и оно предназначено для API-клиентов, а не для UI.

`PUT` больше не создаёт день неявно: день создаётся при первом `POST`/`PATCH` с непустым содержимым.

## 6. Веб-интерфейс

### 6.1 Структура кода

`public/app.js` (2100 строк, два рендерера) разбивается на ES-модули без сборщика:

  store.js        состояние, подписки, оптимистичные обновления

Один набор компонентов на десктоп и телефон, раскладка через CSS-грид и контейнерные запросы, а не через ветвление `isMobile()`. Нижняя навигация на телефоне переключает те же панели, что на десктопе лежат рядом.

```

│ Фокус дня: ______________________________________            │
├──────────────────────────────┬──────────────────────────────┤
│ РАСПИСАНИЕ        [☰] [▦]    │ ПРОГРЕСС                     │

├──────────────────────────────┤  🚭 Не курить ☑ 47/300 · 2   │

```

Полоска `РАБОТА · ДОМ · ПИТАНИЕ` — это три вкладки одного блока: первые две показывают `tasks` с соответствующим `bucket`, третья рендерит секцию питания поверх таблицы `meals` в текущем режиме (§6.6).

Кольца прогресса: общий по дню плюс пять частных — работа, дом, питание, спорт, привычки. Общий считается **без весов**: доля выполненных отмечаемых пунктов от их общего числа по всем секциям сразу (строки расписания, задачи, приёмы пищи, подходы, активные сегодня привычки). Пустые секции в расчёт не входят. Привычки со статусом `skipped` не попадают ни в числитель, ни в знаменатель.

### 6.3 Два вида расписания

Переключатель `[☰] [▦]` в шапке секции, выбор сохраняется в `users.schedule_view`.

- **Список** — компактные строки, лучший вариант для печати и телефона.
- **Таймлайн** — вертикаль часов, высота блока пропорциональна длительности, видны дыры и наложения; край блока тянется для изменения длительности.

Данные одни и те же, различается только отрисовка. На печать всегда идёт список.

### 6.4 Взаимодействия

| Действие | Реализация |
|---|---|
| Переставить строку | Перетаскивание за ручку `⠿` через Pointer Events — работает мышью и пальцем, без библиотек |
| Сдвинуть время | Кнопка `⏱` → `+15 / +30 / −15 / произвольно`, галочка «и все следующие» → `POST .../schedule/shift` |
| Ввод времени | Свободный формат: `9:30`, `930`, `9.30`, `9-11`. Нормализация одна и та же на клиенте и сервере (общий модуль) |
| Будильник | Иконка-цикл на строке: `·` тихо → `🔔` уведомление → `⏰` будильник |
| Повтор | В редакторе строки: нет / каждый день / по будням / по дням недели / каждые N недель, с датой окончания |
| Дублировать, удалить | Контекстное меню строки |
| Копировать день | «⋯ → Скопировать в дату», выбор секций |
| Шаблон | «Сохранить как шаблон» → `series` с именем и без дат, применяется к любому дню |

Повторы работают как в календаре: правило живёт в `series`, конкретный день переопределяет или удаляет только своё вхождение через `series_overrides`, не ломая серию.

### 6.5 Навигация по датам

Полоска ближайших дней со стрелками `‹ ›`, свайп на телефоне, кнопка «Сегодня». Кнопка `📅` открывает месячный календарь с точками заполненности — вспомогательный инструмент за кнопкой, а не основной способ навигации. Отдельного действия «Добавить день» нет: день создаётся сам при первой правке.

### 6.6 Задачи, питание, спорт

Задачи разделены на **Работа** и **Дом** (`tasks.bucket`), питание вынесено в отдельную секцию поверх таблицы `meals`. Режим питания переключается в настройках (`users.food_mode`) и не меняет хранение:

- `checklist` — плоский список с галочками, поле времени скрыто;
- `timed` — показывается время, и записи с заполненным `time_min` дополнительно отображаются в расписании дня (редактируются только из секции «Питание»).

Переключение режима не теряет данные.

Перенос невыполненных рабочих задач на следующий день сохраняется, но становится настройкой (`carry_unfinished_tasks`, по умолчанию включено, отдельно для работы и дома) и выполняется при открытии нового дня, а не при любом сохранении.

### 6.7 Темы

Светлая и тёмная на CSS-переменных, три состояния переключателя: «Системная / Светлая / Тёмная». Значение хранится и в `localStorage` (чтобы не мигало при загрузке), и в `users.theme` (чтобы совпадало между устройствами). Тёмная тема — отдельный набор значений, не инверсия.

Акцентные цвета берутся из иконки: синий `#2E7BE4`, оранжевый `#FF9E1B`, бирюзовый `#22C1D6`.

### 6.8 Брендинг

Из `icon.png` 800×800 генерируются: PWA 192/512 и maskable, favicon, логотип на экранах входа и регистрации, Android adaptive icon (foreground 432 с safe-zone + фоновый слой), legacy mipmap всех плотностей, splash-экраны.

## 7. Привычки

### 7.1 Три независимые оси

| Ось | Поле | Значения | Смысл |
|---|---|---|---|
| Цель | `mode` | `ongoing` · `challenge` | бессрочно или «N дней» с показом «день 47 из 300» |
| При срыве | `break_policy` | `reset` · `keep` | обнулять счётчик или продолжать накопительно |
| Полярность | `polarity` | `do` · `avoid` | «выполнить» или «удержаться»; для `avoid` кнопка называется «Сорвался» |

Оси независимы, все восемь комбинаций осмысленны. Как именно считается счётчик:

| `mode` / `break_policy` | Что показывается | Формула |
|---|---|---|
| `challenge` / `reset` | «День 12 из 30» | Счётчик = текущий стрик подряд от `challenge_start_date`. При `missed` в активный день счётчик обнуляется, `challenge_start_date` сдвигается на следующий день, в историю пишется отметка срыва |
| `challenge` / `keep` | «47 из 300 · 2 срыва» | Счётчик = число `done` от `challenge_start_date` до сегодня. Срывы показываются рядом отдельным числом и не обнуляют счётчик. Челлендж завершён при счётчике = `challenge_target_days` |
| `ongoing` / любое | «Стрик 12 · лучший 40 · 78 %» | Текущий стрик, лучший стрик, процент за выбранный период |

Для `polarity = 'avoid'` семантика лога не меняется: `done` означает «сегодня удержался», кнопка в интерфейсе называется «Сорвался» и ставит `missed`.

Дни, не попадающие в `schedule_mask`, и дни со статусом `skipped` разрывом стрика не считаются и в знаменатель процента не входят.

Дополнительно: `type` (`binary` / `quant` с `target_per_day` и `unit`), `schedule_mask` (в какие дни недели привычка активна), `allowed_skips_per_week` (заморозки, не портящие стрик).

### 7.2 Создание

Форма из трёх полей: **эмодзи · название · пресет**.

| Пресет | Разворачивается в |
|---|---|
| Просто привычка | `ongoing`, `do`, `reset` |
| 30 дней подряд | `challenge`, `challenge_target_days=30`, `break_policy=reset` |
| Марафон 300 дней | `challenge`, `challenge_target_days=300`, `break_policy=keep` |
| Бросаю | `challenge`, `polarity=avoid`, `break_policy=reset` |

Под свёрнутым блоком «Настроить» — все поля по отдельности, включая дни недели, количество в день, заморозки и дату старта челленджа.

### 7.3 Эмодзи-пикер

Собственный: около 600 эмодзи по категориям, поиск по русским названиям, блок «недавние». Данные лежат в `public/js/emoji-data.json`, без CDN — иначе не работает в офлайн-APK. Рядом выбор цвета привычки из восьми, тот же цвет используется в графиках.

### 7.4 Отображение

Карточка: `🚭 Не курить · 47-й день из 300 · 2 срыва · ██████░░ 78%` и точки последних 14 дней. Для `ongoing`: текущий стрик, лучший стрик, процент за период.

Экран управления привычками — полноценный экран, доступный одинаково с десктопа и телефона: из настроек и из вкладки «Привычки». Поддерживает перетаскивание для порядка, архивирование и восстановление.

### 7.5 Статистика

Считается только по дням, когда привычка была активна (`is_active`, не в архиве, `date >= created_at`) и попадала в свой `schedule_mask`. `skipped` не входит в знаменатель. Периоды 7 / 30 / 90 / всё. Графики — inline SVG без библиотек, читаемые в обеих темах.

## 8. Уведомления, будильник, Android

### 8.1 Каналы уведомлений

| Канал | Где | Механизм |
|---|---|---|
| Локальные | Android, офлайн | `AlarmManager`, планируются на устройстве |
| Web Push | Десктоп Chrome/Edge/Firefox | VAPID + service worker, работает при закрытой вкладке |
| В приложении | Открытая вкладка | Тост и звук |

Настройки: глобальный выключатель → «за сколько предупреждать» по умолчанию (5/10/15/30 мин) → тихие часы. На строке расписания можно переопределить `remind_before_min` или выключить.

Серверный планировщик наполняет `notification_queue` в таймзоне пользователя и отправляет Web Push. Android независимо планирует всё на сутки вперёд локально, чтобы отсутствие сети ничего не ломало; дубли гасятся по идентификатору события.

### 8.2 Нативный плагин будильника

Kotlin, Capacitor-плагин в `android/app/src/main/java/ru/appswire/newday/alarm/`.

| Требование | Механизм |
|---|---|
| Точный запуск, переживает Doze | `AlarmManager.setAlarmClock()` |
| Разрешение на точные будильники (Android 12+) | `SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM` |
| Поверх локскрина, экран включается | Full-screen intent + `setShowWhenLocked` + `setTurnScreenOn` |
| Звук в беззвучном и «Не беспокоить» | `AudioManager.STREAM_ALARM`, канал уведомлений с `bypassDnd` |
| Процесс не убивают во время звонка | Foreground service |
| Экран не гаснет | `WakeLock` |
| Переживает перезагрузку | `BOOT_COMPLETED` — перепланирование |
| Автозапуск на Xiaomi/Huawei/Samsung | Подсказка с кнопкой в нужный системный экран |

### 8.3 Экран «Проверка будильника»

Разрешения не выпрашиваются пачкой при первом запуске. Отдельный экран со списком требований, у каждого статус ✓/✗ и кнопка «Исправить», ведущая ровно в нужный системный экран. Внизу — **«Тестовый будильник через 1 минуту»**.

### 8.4 Задачи для отключения

Три типа, все реализуются сразу:

1. **Пример** — арифметика с четырьмя вариантами ответа, три уровня сложности.
2. **Код** — ввести показанную последовательность цифр.
3. **Иконки** — нажать три показанные иконки в правильном порядке.

Настройки: какие типы в пуле, количество задач 1–5, сложность, таймаут на задачу (по умолчанию 30 сек). По истечении таймаута задача меняется, звук не смолкает.

### 8.5 Профили будильника

- `wakeup` — строгий: задачи обязательны, нарастающая громкость до максимума, вибрация, «Отложить» недоступно при включённом строгом режиме.
- `gentle` — мягкий: одна задача или без задач, тише, «Отложить 5 мин» доступно. Для совещаний и дневного сна.

Будильники не отдельный список, а флаг на строке расписания (`alarm_mode` + `alarm_profile`). Настройка «Будить по первой активности дня» по умолчанию включена и автоматически ставит `⏰ wakeup` на первую строку — её можно снять вручную.

### 8.6 Android-приложение

Capacitor 6, веб-ассеты вшиты в APK (`capacitor.config.json` без `server.url`). Локальный кеш дня и настроек в `localStorage`/IndexedDB, синхронизация с сервером при появлении сети; расписание на ближайшие сутки всегда доступно офлайн для планирования будильников.

Дополнительно: сканер QR для входа (ML Kit), нативные локальные уведомления, `android/` убирается из `.gitignore` и коммитится.

### 8.7 Тестирование на эмуляторе

AVD `Pixel_7` и `Medium_Phone_API_36.1`. Обязательные сценарии, каждый с логом:

1. Заблокированный экран.
2. Беззвучный режим.
3. Режим «Не беспокоить».
4. Doze — `adb shell dumpsys deviceidle force-idle`.
5. Перезагрузка устройства до срабатывания.
6. Приложение убито из недавних.
7. Смена системного времени и часового пояса.
8. Отсутствие сети.

Будильник обязан сработать во всех восьми.

### 8.8 Распространение APK

Три точки входа: настройки → «Приложения» с кнопкой и QR; закрываемая плашка при первом заходе с Android-браузера; мелкая ссылка в подвале страницы входа. Файл лежит в `public/downloads/`, рядом показываются версия и дата сборки.

## 12. Что не входит

- iOS-приложение.
- Синхронизация с внешними календарями.
- Совместные и командные функции, шаринг дней.
- Встроенный LLM-ассистент: проект отдаёт API, клиента к модели не содержит.
- Мобильный будильник на iOS и в десктопном браузере: технически невозможно обеспечить надёжность, вместо него — Web Push.
