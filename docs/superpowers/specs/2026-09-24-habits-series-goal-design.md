# Привычки: «Серия» и «Цель» вместо «Выполнять/Бросаю»

Дата: 2026-09-24. Статус: одобрено в диалоге.

## Зачем

Три беды, у которых один корень — вид привычки не определяет, как её считают.

**Выбор без смысла.** «Выполнять / Бросаю» (`polarity`) не участвует в
подсчёте нигде: он меняет только подпись-подсказку в шторке. Человек выбирает
и ждёт, что от этого что-то зависит.

**Нужного выбора нет.** В базе два способа считать заложены
(`break_policy`: `reset` — обнулять при срыве, `keep` — копить), но веб-версия
всегда ставит `reset`. Поэтому любая цель — «N дней подряд», и один пропуск
сбрасывает счёт в ноль. Отсюда «Спартанец: челлендж 0 из 300» при десятках
отмеченных дней: показывается не сделанное, а текущая серия.

**Двух разных вещей не различить.** Есть привычки, где важна непрерывность
(не курить, душ, чтение), и есть «сделать столько-то раз», где пропущенный
день — не срыв, а просто не в зачёт: не отметился и пошёл дальше.

## Два вида

**Серия** — сколько раз подряд. Дни недели задают, где серия живёт: пропуск
выбранного дня обнуляет счёт, невыбранный день — законный выходной и серию не
рвёт.

**Цель** — сколько раз всего. Каждая отметка добавляет единицу; пропуск не
штрафуется и ничего не обнуляет. Дни недели у Цели тоже можно задать, но они
ни на что не влияют: это план и напоминание, не обязательство. Пропустил
среду — вернулся в пятницу, счёт не пострадал.

Число в обоих видах необязательно:

| | с числом | без числа (∞) |
|---|---|---|
| Серия | «12 из 30 подряд», цель взята на 30-й | «подряд 12 дней», растёт бесконечно |
| Цель | «12 из 30» | «сделано 12 раз» — просто счётчик |

Счётчик без числа — отдельный сценарий, а не вырожденный случай: «отжимания:
было 30, стало 31» отмечают каждый раз, когда превзошли себя, и смысл в самом
числе повторений.

## Подсчёт

| | Серия | Цель |
|---|---|---|
| Счёт | дни подряд | число отметок |
| Пропуск активного дня | обнуляет | не влияет |
| Дни недели | определяют активные дни | только план |
| Лучшая серия | есть | нет |
| Срывы | считаем | не считаем |
| Проценты | сделано из обещанного | сделано из цели; без цели — нет процентов |
| Полоска за 14 дней | пропущенный день красный | пропущенный день пустой |

**Плитка «серия привычек»** (сколько дней подряд закрыты все привычки) считает
только Серии. Непроставленная Цель законна, и рвать общую серию ею нельзя.

## Что в базе

Новых колонок не нужно — оба способа уже есть. Вид выводится из имеющихся
полей, и это же даёт правило для всех нынешних привычек:

```
вид = (break_policy === 'keep' || times_per_week > 0) ? 'цель' : 'серия'
цель = challenge_target_days   // null — значит без числа
```

Свободный график («N раз в неделю») читается как Цель: серия подряд для него
не считалась и раньше — показывала ноль.

Все нынешние привычки записаны с `break_policy = 'reset'`, значит все станут
Сериями — то есть ровно тем, чем были. Переключение вида отметок не трогает:
журнал лежит отдельно, и «Спартанец», переведённый в Цель, сразу покажет,
сколько дней на самом деле отбегали.

`polarity` остаётся в базе и в API (им пользуются готовые наборы и
интеграции), но из веб-версии уходит: выбор, ни на что не влияющий, хуже
отсутствия выбора.

## Что отдаёт сервер

`habitStats` получает явный вид и общее число отметок:

```js
{
  kind: 'series' | 'goal',
  target: 30 | null,
  total: 46,            // всего отметок «сделано» за всю жизнь привычки
  currentStreak: 12,    // 0 у Цели
  bestStreak: 30,       // 0 у Цели
  done, missed, skipped,
  percent,              // Серия: done/(done+missed); Цель с целью: total/target; Цель без цели: null
  challenge: { day, target, breaks, complete, startDate } | null,
  week, last14,
}
```

`challenge` остаётся ради совместимости (его читают страницы `habits.js` и
`stats.js`), но считается по виду: у Серии `day` — текущая серия, у Цели
`day` — накопленное число отметок, `breaks` — всегда 0.

У Цели: `missed = 0`, а в `last14` прошедший неотмеченный день получает
`null`, а не `missed` — иначе полоска рисует срывы там, где их нет.

Два уточнения, чтобы их не пришлось додумывать:

- `total` считается за всю жизнь привычки, `challenge.day` — от даты начала
  цели (`challenge_start_date`). Обычно это одно и то же число; расходятся
  они, если цель поставили привычке, которую уже вели.
- `percent` у Цели не превышает 100: перевыполненная цель — это «цель взята»,
  а не «137 %».

## Что видно человеку (веб-версия)

- Вместо «Выполнять / Бросаю» — **«Серия / Цель»** с подсказкой под выбором,
  как сейчас сделано для «выполнить»:
  - серия: отмечаете каждый выбранный день; пропуск обнуляет счёт;
  - цель: отмечаете, когда сделали; пропуск не в зачёт, но счёт не обнуляет.
- Блок цели меняет подпись по виду: у Серии «сколько дней подряд», у Цели
  «сколько раз». Варианты те же: 30, 100, ∞, своё.
- График: у Цели — «по дням недели» или «N раз в неделю»; у Серии выбор
  графика только по дням: «подряд» требует конкретных дней, и сочетание
  «серия + N раз в неделю» раньше молча показывало ноль.
- Подписи в списке: у Серии «подряд 12 дней · лучшая 30», у Цели «12 из 30»
  или «сделано 12 раз» — без слова «подряд» и без лучшей серии.

## Чего не делаем

- Не трогаем старые страницы `/habits.html` и `/stats.html`: это прежняя
  оболочка, она читает `challenge.day` и продолжит работать. Переписывать её
  ради новых слов — работа, которой человек не увидит.
- Не добавляем колонок в базу и не переносим данные.
- Ачивки за серии и цели — отдельный разговор после этой работы.

## Проверки

Серверные тесты (`test/services/stats.test.js`):

- Цель: пропущенный день не обнуляет счёт и не попадает в срывы; счёт равен
  числу отметок; лучшей серии нет;
- Серия: пропуск обнуляет; выходной по маске — не обнуляет;
- Цель без числа: счётчик растёт, процентов нет;
- плитка «серия привычек» не ломается от непроставленной Цели;
- свободный график читается как Цель.

Живые пробы (`tools/web-live-check.mjs`): создать Серию и Цель через шторку,
отметить, проверить подписи и то, что у Цели нет «лучшей серии».
